# RelicCommerce

Small, accountless order and offline-license fulfillment service for Stillmark. It is
disabled until all required server-only settings are supplied; no Stripe, signing, or mail secret
is committed here.

## Configuration

The service requires these environment variables (or equivalent ASP.NET configuration keys):

| Setting | Purpose |
| --- | --- |
| `RelicCommerce__Enabled` | Must be `true` to enable checkout/webhook/retrieval. Defaults to `false`. |
| `RelicCommerce__DatabasePath` | SQLite file path. Defaults to `relic-commerce.db`. Use durable storage in production. |
| `RelicCommerce__StripeSecretKey` | Stripe secret key, kept server-side. |
| `RelicCommerce__StripeWebhookSecret` | Endpoint signing secret (`whsec_...`). |
| `RelicCommerce__StripePriceId` | The single approved one-time price ID. |
| `RelicCommerce__Currency` | Must be lower-case `usd` for the approved $30.00 one-time offer. |
| `RelicCommerce__ApplicationMajor` | Major version granted by the approved price. |
| `RelicCommerce__Edition` | Edition granted by the approved price. |
| `RelicCommerce__ManagedPayments` | `true` enables `managed_payments[enabled]=true`; `false` uses ordinary Checkout. |
| `RelicCommerce__SuccessUrl` | First-party success URL containing `{CHECKOUT_SESSION_ID}`. |
| `RelicCommerce__CancelUrl` | First-party cancel URL. |
| `RelicCommerce__PrivateKeyPem` | Encrypted PKCS#8 PEM generated by `WinShot.KeyGen`. |
| `RelicCommerce__PrivateKeyPassphrase` | Passphrase for that PEM. |
| `RelicCommerce__SmtpHost` / `SmtpPort` | Reserved SMTP transport settings for the durable outbox. |
| `RelicCommerce__SmtpUser` / `SmtpPassword` / `SmtpFrom` | Reserved SMTP credentials and sender; no mail is sent by this service yet. |

The PEM and passphrase are loaded only at startup. Put them in a secret store in production. The
service imports the PEM at startup and requires its public key to exactly match the desktop
verifier embedded in `WinShot.Licensing`; a malformed or mismatched key prevents startup before
checkout can accept payment. The service never stores the bearer license key; it reconstructs the
same signed payload on retrieval.

The checkout route returns a `303` redirect to Stripe, so a static website can use a normal
same-origin form action and does not need CORS or Stripe.js.

## Local test mode

Set the required values to Stripe test values and run `dotnet run`. Forward test webhooks with:

```powershell
stripe listen --forward-to http://localhost:5000/api/stripe/webhook
```

Use Stripe's test card `4242 4242 4242 4242`. The service fulfills only a paid Session containing
the exact configured price, **$30.00 USD**, quantity 1, product metadata, and mode. A success redirect is
not a payment proof.

The public website must remain disabled until the endpoint, offer terms, release, and policies are
approved. No email recovery endpoint is exposed by this minimal service; retrieval uses a
high-entropy token returned only after a verified paid Session. The Checkout Session ID is itself a
bearer recovery capability, so keep the success URL free of analytics parameters and third-party
referrers. Retrieval is available for three days from the purchase timestamp; adding mail delivery
later should be a separate, idempotent outbox change.

The entitlement timestamp is the signed webhook event's `created` time for the successful payment
event. A repeated delivery reuses that same timestamp, while a later duplicate event cannot move
the existing order's update cutoff. Confirmed refunds and disputes durably block the payment intent,
including when Stripe delivers that event before the successful Checkout event. Any confirmed
refund, including a partial refund, blocks this one-time license; pending or failed `refund.created`
events do not.

Refund and dispute blocking stops future fulfillment and redemption through this service. An offline
signed license already delivered and activated by the desktop app cannot be remotely revoked by
this service.
